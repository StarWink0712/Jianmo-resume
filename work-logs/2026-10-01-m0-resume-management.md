# 2026-10-01 / M0 / 多简历管理与独立副本

时区：Asia/Shanghai。用户明确要求管理多份简历，并通过旧简历快速创建副本、独立编辑新版本，同时保留旧简历。

## 范围与决策

多简历已在范围基线内，本次补齐可操作入口，仍属于 M0 原型。没有增加数据库、持久化、PDF 编译或照片上传。页面顶部明确提示仅本次内存保留，刷新/关闭即重置。

复制默认读取已保存快照；有未保存草稿时提供显式版本选择。副本与源简历使用不同 ID，各自拥有内容、修订和预览，副本从 r1 且未编译开始。复制本身不更改源简历。生产内部 ID、附件引用重建和事务要求补入数据契约，未冒充已实现。

## 改动

| 内容 | 结果 |
| --- | --- |
| 我的简历 | 默认管理入口、卡片、搜索、创建空白/示例、复制、重命名、删除确认 |
| 编辑器 | 当前简历选择器、返回列表、复制/重命名入口，沿用蓝白双栏布局 |
| 独立模型 | `docs/m0/resume-library.js`，深复制草稿与保存快照，保存/编译任务绑定简历和任务 ID |
| 切换保护 | 各自恢复草稿、标签、缩放、保存状态及预览；目标处理中的管理操作禁用 |
| 文档 | 更新范围、数据契约、交互说明、README 及日志索引 |
| 自动测试 | `tests/resume-library.test.cjs`，Node 内置测试，无新增依赖 |

先编写测试，初次因缺少模型模块按预期失败；实现后 14 项模型测试通过。原有 24 项 Python 契约测试与 22 个数据场景继续作为回归基线。

## 限制

M0 不是可持久化的产品；管理对象不替代正式 JSON Schema。真实 SQLite 事务、备份导入、附件复制、多标签页并发和 PDF 编译仍未实现。后续进入 M1 的门槛不变，未提交 Git。
