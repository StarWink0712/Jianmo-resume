# M0 范围基线

版本：0.1 / 日期：2026-10-01（Asia/Shanghai）

状态：根据原规划采用的开发执行基线。用户已授权启动 M0；下列细节是可追踪的默认决策，不声称获得逐项人工确认。M1 如发现不可行，必须记录变更，不能静默降低承诺。

## 1. 首版边界

| 项目 | 冻结基线 |
| --- | --- |
| 系统 | macOS 14+、Apple Silicon；最低系统版本仍需实测 |
| 浏览器 | 目标系统自带 Safari 与发布时 Chrome 稳定版 |
| 架构 | React + TypeScript 静态前端、Python + FastAPI 本地单体、SQLite、受控 LaTeX 子进程 |
| 使用 | 首次联网安装；之后核心流程可离线；用户无需另装 Node/Python/LaTeX |
| 数据 | 默认只在本机保存；无账户、遥测、云端编译、AI、远程字体 |
| 简历 | 支持多份独立简历；新建空白、从虚构示例新建、复制、重命名、删除 |
| 内容 | 固定基本信息区；可增删、改名、排序及隐藏的教育、工作/实习、项目、技能、自定义模块 |
| 照片 | 可选单张头像，PNG/JPEG；不支持 Markdown 图片或 SVG 上传 |
| 模板 | 仅 `cn-single-column`，模板版本 `0.1.0`；纸张仅 A4 |
| 输出 | 真实 PDF 预览及同文件下载；一份简历的工程备份与恢复 |
| 非目标 | Intel 正式支持、Windows/Linux、账户、收费、在线分享、云同步、任意 TeX 导入、画布排版、Word 导出、协作 |

不得把岗位内容示例当成排版模板。示例只复制结构化内容；模板负责布局，不携带用户经历或预设岗位事实。

用户已于 2026-10-01 明确强调多份简历管理和“保留旧简历、复制后编辑新简历”的使用流程。管理页为默认入口；复制默认使用已保存版本，存在未保存草稿时提供显式选择。副本与原简历的数据、修订和编译任务独立，删除任意一份不级联删除其他副本。M0 先演示内存中的完整操作，持久化仍由后续 SQLite 实现承担。

## 2. 第一套模板规格

自建中文单栏模板，信息顺序为基本信息区与用户排序后的可见模块。姓名、求职方向、联系方式置顶；头像可选，位于右上角，隐藏头像后不留空槽。正文黑色、标题加粗与细分隔线，不使用依赖字体图标的联系方式标记。

| 设置 | 默认 | 可调范围 |
| --- | --- | --- |
| 正文字号 | 10.5 pt | 10–12 pt，步长 0.5 |
| 行距系数 | 1.2 | 1.1–1.5，步长 0.05 |
| 模块间距 | 8 pt | 4–16 pt，步长 1 |
| 条目间距 | 4 pt | 2–10 pt，步长 1 |
| 四边页边距 | 16 mm | 各 12–24 mm，步长 1 |

姓名字号暂定 20 pt，模块标题暂定 12 pt；具体字体文件、字重映射、分页策略和宏包由 M1 实测选定。无一键强制压成一页功能；长内容自然分页，标题须与后续内容保持关联。M0 的“一页/两页样例”是布局目标，不是编译结果。

## 3. 内容编辑规则

- 基本信息允许空白草稿；姓名为空时给出完整性提醒，不阻止保存或编译空白测试样例。标题默认“未命名简历”，不能为空。
- 教育、工作、项目条目使用结构化日期，精度为月；允许起止日期未知。结束时间为空不自动等于“至今”，只有 `ongoing=true` 表示至今。
- 模块和条目的数组顺序就是唯一顺序；不另存 `order`，避免排序冲突。隐藏内容仍保存在数据库和工程备份中。
- 删除简历、模块、条目和移除头像均先确认；取消不改变数据。键盘可使用“上移/下移”，不把拖拽作为唯一排序方式。
- 文本支持段落、加粗、斜体、有序/无序列表、安全链接；列表最多嵌套 2 层。完整 Markdown 规则见数据契约。
- 样式与模板改变也形成新修订。模板可用性不决定草稿能否保存；编译失败保留内容和上一次成功 PDF。
