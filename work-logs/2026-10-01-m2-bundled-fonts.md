# M2 统一字体与安装可携带性

## 目的与决策

用户希望 PDF 使用编辑界面类似的无衬线字体，并要求其他人的电脑安装后使用同一字体。
原 CSS 是 Avenir Next / PingFang SC / Microsoft YaHei 系统回退链，不能保证跨电脑一致，也不能直接再分发苹果字体。
采用 Noto Sans CJK SC 2.004 普通体/粗体搭配 Noto Sans 2.008 西文四字形，界面和 PDF 共用六份原始字体文件；原始 OFL 和来源、版权说明一并打包。

## 改动

- 字体资源固定大小/SHA-256；启动、构建和编译验证。缺失或损坏失败，不退回系统字体。
- CSS 使用运行时提供的本地 URL；六个 FontFace 都验证加载状态，失败给出可见提示。
- XeLaTeX 使用明确文件路径，中英文采用同系列字体；中文斜体固定倾斜，西文斜体及粗体使用真实字形。
- PDF 校验增加字体名称限制；缓存指纹包含字体契约。系统字体读取在沙箱中被拒绝。
- 新包版本独立安装，保留旧版本；新增源码和系统字体不可读的隔离探针。
- 不更改真实用户简历字段、排版参数或版本，不把个人内容写入测试夹具和本日志。

## 已执行

- FontTools 只读核对两份字体：Version 2.004，fsType=0，常用中英文、箭头、列表符号均有字形。
- 开发编译探针：成功、无缺字或溢出，PDF 内嵌 Noto Regular/Bold，带 Unicode 映射。
- Python 单元回归：91 项通过；Node 历史状态回归：14 项通过。
- 完整冻结运行时重新构建成功；最终包大小 72,195,836 字节，233 项清单，SHA-256 为 `9626759d9b608e6dabcefa23e87bd8ed22ae307e769df18cb2bea50afbe98936`。

初次安装回归发现两项失败并已定位：空白 PDF 合法地没有字体资源，校验改为结合独立的文本完整性检查；CJK 字库的 ASCII hyphen 和 non-breaking hyphen 共用字形，PDF 提取把普通连字符变成了不换行连字符。
没有放宽或归一化文本比对；改用同系列 Noto Sans 西文字体保留两种字符的不同映射，并添加普通/不换行连字符、箭头、真实斜体/粗斜体的端到端回归。
