# 2026-10-02：跨机 TeX 格式生成与源码启动

## 用户要求与诊断

用户在另一台电脑克隆后遇到 `xelatex.fmt` 与旧基线不一致，要求正式更新 M1 基线而不是修改单个哈希；最终目标是少量命令从源码启动。当前可操作机器仍拥有旧宿主格式哈希，未连接到用户的新电脑，也未把新电脑的短哈希擅自登记为可信输入。

问题是旧构建器把机器生成的格式缓存当成跨机器源输入，并把单份旧简历的 recorder 记录作为打包种子。后续安装器缺失是构建失败的连锁结果。

## 实现

- 从 `xelatex.ini` 在项目私有目录和禁网沙箱生成 `xelatex.fmt`，使用明确环境、格式目录和项目配置，不读取或修改宿主预生成格式与根目录定制配置。
- 在正式基线中记录所有有效用例的依赖并集、248 个格式生成源文件、引擎、字体、CMap 与明确打包资源。源文件仍逐项校验，新生成格式以本次构建哈希纳入安装清单，不要求等于原电脑的缓存哈希。
- 新增候选、差异审核和显式批准流程，绑定清单/结果/验证实现摘要与审核文件。实验不会自动覆盖正式基线；单个哈希修改、少采样、失败结果或过期证据不能被正常构建器接受。旧基线与结果保存在 `docs/m1/baseline-history/`。
- 构建前先校验源基线，冻结运行时必须先通过真实 PDF 自检才产生新安装包；安装器原有大小/SHA-256/文件/权限检查保留。
- 新增 `scripts/start-local.sh` 自动创建环境、安装依赖、准备缺失/基线过旧的运行时、自检并启动后端；`set -eu` 阻止构建失败后继续安装。TeX 根目录及 Homebrew 前缀由工具发现，不固定原机安装位置。
- 双语 README 改成前置依赖加三条克隆/启动命令；详细问题处理与维护流程见 `docs/m1/tex-baseline-update.md`。没有修改用户简历内容，也没有向远端推送。
- `.gitattributes` 固定文本 LF、标记字体/图片/PDF/ZIP 为二进制，避免另一台电脑的 Git 换行设置无意改变审核证据或脚本字节。

源码启动测试的新虚拟环境和产物在测试后清理，仅保留忽略目录内诊断日志和脱敏汇总。为了避免扩大仓库，只记录公开清单与证据，不提交运行时压缩包。

过程中发现完整 TeX 树在受控配置下搜索不存在字体可能变慢，开发实验改用 TeX Live 的 `ls-R` 数据库搜索，未扩大沙箱权限；生成格式目录只为明确格式文件增加只读许可。早期失败候选没有批准，最终证据来自完整重跑。无修改系统格式缓存、无跳过源哈希或 PDF 检查。

## 真实范围

当前支持 macOS Apple Silicon 和已批准的 TeX Live 2026 源输入。首启依赖 Homebrew/Python/TeX，需要联网安装 Python 包；不是无需依赖的小型桌面安装包。真正上游源版本变化仍需维护者审核，不能承诺任意未来版本直接兼容。没有把原机器上独立源码目录测试写成干净 Mac 或用户新电脑验收，也没有公开预构建下载、签名/公证或完整再分发许可结论。
