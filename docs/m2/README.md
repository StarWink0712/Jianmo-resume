# M2 本地后端

本轮将 M0 原型中的保存、编译和导出接成真实流程，使用 FastAPI + SQLite + 单工作线程编译队列。浏览器继续沿用原蓝白双栏布局，暂用原生模块 JS；本地 PDF.js 5.6.205 负责真实 PDF 渲染，不再依赖内嵌浏览器原生 PDF 插件。

## 启动与退出

```bash
.venv/bin/python -m pip install -r requirements-app.txt
.venv/bin/python -m backend
```

从项目根目录启动，打开 `http://127.0.0.1:8770/`。当前开发机已有专用 TeX，不需安装新的 LaTeX。依赖的准备和安装见 [M1 运行时](../m1/managed-runtime.md)。新后端尚未打进该安装包。

可选参数：`--port 8770`、`--data-dir /absolute/private/directory`、`--runtime /absolute/runtime/root`。只绑定 `127.0.0.1`，不能改为公网监听；同一数据目录只允许一个服务实例。端口被占用会退出，不会自动接管其他服务。不要用 `file://` 或另一个 Host 打开页面。

按 `Ctrl+C` 退出。排队任务被取消，正在编译的任务在其超时边界内收尾。异常退出后，再启动会将残留的排队/运行任务标记失败，可手动重试。

## 使用流程

1. 在“我的简历”新建空白简历或虚构示例，也可从旧简历创建独立副本。
2. 停止输入约 1 秒后自动保存。成功提示代表 SQLite 事务已提交，不是前端模拟。
3. 点击“保存并预览”生成 PDF。普通自动保存不自动触发编译。
4. 预览页使用同一编译任务的 PDF 字节，可翻页、缩放、下载，无水印。
5. 修改后旧 PDF 会标注旧修订，最新版导出暂时禁用；用户确认后仍可导出上次成功版本。
6. 多页面冲突时，本页草稿保留。可以另存独立副本，或明确丢弃本页输入并加载最新修订。
7. 工程备份包含 JSON、头像和 SHA-256 清单。导入总是生成新 ID，不覆盖原简历；不包含历史修订、编译缓存或 PDF。

基本信息在 PDF 顶部居中。性别和年龄有独立选填字段，清空后不显示；个人链接的显示文字也可留空，此时只显示网址，不补默认名称。旧简历和旧备份缺少性别/年龄字段时仍可打开、编辑和导入，不自动改写历史内容。

基本信息的“上传头像/更换头像”先打开裁剪窗口，支持拖动、方向键移动、缩放、旋转和重置，确认后保存为 600×800 的 3:4 竖版头像。取消或 Escape 不替换原头像；已有照片可通过“调整头像”再次裁剪，需要找回已裁掉的部分时重新上传原图。原图仍仅支持 JPG/JPEG/PNG 且不超过 1 MB，读取尺寸后再解码；裁剪和字体资源均在本机。PDF 头像上限为 24×32 mm，保持比例及基本信息居中；旧头像不会自动被裁剪。

首次进入没有自动塞入个人简历。当前开发实例可能保留本轮 UI 验证创建的、名称带 M2/测试的虚构样例。

## 数据与并发

默认私有数据目录为 `.local-data/`，已加入 Git 忽略。`resumes.sqlite3` 中保存当前修订指针、不可变历史 JSON、内容哈希寻址的头像 BLOB 和成功 PDF。使用 WAL、`synchronous=FULL`、事务和修订号检查；重复保存未变化内容不增加修订。头像与修订同事务提交。

不要在服务运行时只复制主数据库文件而忽略 WAL。常规备份请使用页面“工程备份”；若要保存整个数据目录，应先正常退出服务，再备份整个目录。

副本重新生成简历、链接、模块、条目和附件 ID，并不继承源 PDF/任务。不可变头像可以在物理存储中按哈希复用，但删除或编辑源简历不会修改副本。

队列一次只运行一个任务，最多 32 个排队/运行任务。任务固定读取某个已保存修订；保存新修订不修改正在编译的快照。相同构建键的排队、运行或成功任务复用，失败任务可重新提交。构建键包含简历 ID、修订、模板、TeX 清单和渲染实现指纹；旧任务不被当作新修订的成功 PDF。

保存允许与编译并行；源简历正在编译时，重命名、删除和复制被拒绝。前后端都会检查，不只依赖按钮禁用。

## 安全边界

只面向本机单用户，不是多用户鉴权系统。Host、Origin、随机会话令牌和 JSON 类型检查阻止普通跨站访问。令牌不写 URL、本地存储或普通访问日志，服务重启会轮换；页面可重新取令牌后重试，不要求先丢弃输入。数据库不加密，同一操作系统用户的其他进程不在隔离边界之外。

编译采用可信模板和 Markdown AST 白名单，TeX 控制字符转义，拒绝 HTML、代码、图片及非法链接。不可编译但结构有效的 Markdown 草稿允许保存，随后编译明确失败。引擎禁网络、禁 shell escape，并限制读写目录；沿用 M1 的 CPU/时间/单文件限制与 512 MiB RSS 采样保护，**这不是硬内存上限**。

API JSON 上限 2 MiB，新头像上传支持 JPG/JPEG、PNG，原文件不超过 1 MB（1,000,000 字节），ZIP 25 MiB。头像无固定长宽或比例要求，后台保留有效解码与总像素资源保护；校正 EXIF 方向后等比例优化到最长边 1024 像素，转为去元数据、白底的 PNG。历史存储头像和备份继续兼容原 5 MiB/4096 元数据契约。导入仅接受已知工程成员，拒绝路径穿越、符号链接、重复成员、加密及超大解压内容，校验清单和附件。

PDF.js 的构建产物与 Apache-2.0 许可保存在 `web/vendor/pdfjs/`，没有 CDN 请求。前端没有 analytics、遥测导出器、云账户或上传到外网的接口。

## 验证命令

```bash
.venv/bin/python -m unittest discover -s tests -v
node --test tests/resume-library.test.cjs
node --check web/app.js
node --check web/viewer.js
.venv/bin/python -m pip check
.venv/bin/python scripts/check_backend.py
```

自检默认使用空闲端口 8771，可用 `--port` 调整；在 `tmp/m2/` 下创建临时数据目录，用虚构数据启动真实子进程、重启、编译和恢复。不会操作 `.local-data/`，结束后清理临时数据库；输出 `docs/m2/results.json` 和两份基准 PDF。自检报告不记录令牌、真实简历或个人绝对路径。
