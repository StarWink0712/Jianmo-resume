# 数据与备份契约 v1

状态：M0 执行基线；Schema 文件为结构约束，本文约定语义。数据库布局和 HTTP 路由尚未冻结。

## 1. 简历对象

对应 `schemas/resume.schema.json`。编码 UTF-8，未知字段拒绝，不静默丢弃；所有 ID 为 1–64 位小写 ASCII 标识符，字母开头，后续可含数字、下划线和连字符。实际创建使用带类型前缀的随机 UUID，示例使用可读 ID。

| 字段 | 语义 |
| --- | --- |
| `schema_version` | 内容协议版本，当前整数 1；与数据库迁移版本、模板版本独立 |
| `id` / `revision` | 简历稳定 ID；持久化成功后从 1 开始单调递增 |
| `title` | 简历管理标题，不打印在 PDF 中；1–80 字符且不能全空白 |
| `basics` | `name`、`headline`、`email`、`phone`、`location`、`links`、`avatar_attachment_id`、`avatar_visible`；M2 增补可选 `gender`、`age` |
| `sections` | 模块数组；每个模块有稳定 `id`、`type`、可改 `title`、`visible`、`entries` |
| `template` | `id=cn-single-column`、`version=0.1.0` |
| `style` | A4、字号、行距、模块/条目间距及四边页边距；单位写在字段名中 |
| `attachments` | 当前头像的元数据；`avatar_visible=false` 仅隐藏、不删除；移除须确认并同时清除引用与元数据，未引用附件不可打包 |
| `created_at` / `updated_at` | UTC RFC 3339 秒级时间，如 `2026-10-01T10:00:00Z`；更新不得早于创建 |

`basics` 固定存在，可填空字符串。电话保留用户格式，不做数字转换；邮箱在保存草稿时不作严格 RFC 校验，格式提醒由 UI 处理，绝不把字段当 HTML/TeX 指令。联系链接为 `{id,label,url}`，最多 6 个，只允许绝对 HTTP/HTTPS URL，无凭据、控制字符或反斜杠。首版不自动抓取链接，也不加载链接内容。

2026-10-01 M2 增补：`gender` 是最多 20 字的选填字符串，空字符串不显示；`age` 是 0–150 的整数或 null，null/缺失不显示，不从姓名、求职意向或日期自动推断。年龄清空必须写入 null，不能变成 0；填写 0 时可明确显示 0 岁。新建简历默认包含 `gender=""`、`age=null`。旧 v1 数据可缺少这两个字段，新版按未填写处理，不修改历史修订。属于当前开发版 v1 的可选字段扩展；旧程序的严格 schema 可能拒绝带新字段的备份，不声明新版备份可回导旧程序。

`links[].label` 可为空或仅空白。此时直接显示可点击的网址，不添加 `Link`、`个人主页`等占位名称；非空时显示去除首尾空白后的名称。留空不代表删除或隐藏整条链接。PDF 顶部基本信息居中，性别/年龄/所在地、电话/邮箱、个人链接分行；隐藏或缺失的字段不生成占位符。

模块最多 20 个，每模块最多 100 个条目；正文最多 10,000 字符，普通标题/名称最多 200 字符，URL 最多 2,048 字符。保存请求及备份中的 `resume.json` 最多 2 MiB UTF-8；总大小限制与单字段限制同时生效。

## 2. 模块字段

所有条目都有 `id`、`visible`、`body`。`body` 是受限 Markdown 字符串，允许空白。教育、工作和项目另有 `start_date`、`end_date`（`YYYY-MM` 或 null）、`ongoing`。`ongoing=true` 时结束日期必须为 null；两个日期都有值时结束月份不早于开始月份。

| 模块 `type` | 专有字段 | 表单与打印含义 |
| --- | --- | --- |
| `education` | `school`、`degree`、`field_of_study`、`location` | 学校、学历/学位、专业、地点；正文承载课程或补充说明 |
| `employment` | `organization`、`role`、`employment_type`、`location` | 单位、职位、工作类别（`full_time/part_time/internship/other`）、地点 |
| `project` | `name`、`role`、`url`（null 或 URL） | 项目名、职责、可选链接；正文承载描述和成果 |
| `skills` | `label` | 技能分组名及正文，例如“语言与框架” |
| `custom` | `heading` | 自定义条目标题及正文，适合奖项、证书、个人简介 |

2026-10-01 M2 增补：新增 `academic`（学术成果）和 `competition`（竞赛成果），以及结构化自定义模块；条目采用 `heading`、`role`、`start_date`、`end_date`、`ongoing`、`url`、`body`。旧自定义条目可缺少新增元数据，读取不自动写回；新增自定义和新成果类型使用完整字段。正式 `awards` 类型与 `skills` 保持直接正文模式。详细兼容、表单与 PDF 约定见 [M2 成果模块](../m2/achievement-modules.md)。

固定基本信息区不参与模块排序。模块可重复使用同一类型，展示标题不决定类型。简历内的模块、条目、链接、附件 ID 全局不重复；排序和显隐不改 ID。对隐藏内容同样执行输入安全检查，不能借隐藏状态绕过规则。

## 3. 受限 Markdown

采用 CommonMark 的段落、强调、强强调、有序/无序列表、行内链接语义；列表总深度最多 2，有序列表起始序号保留。普通换行按段内软换行处理，空行分段。M2 增加显式换行：行末两个空格或反斜杠后接换行，渲染为同段内的新一行，不添加列表符号；工具栏“换行”按钮生成前一种写法。不支持标题、表格、引用、代码块/行内代码、图片、任务列表、删除线、自动链接、原始 HTML 或数学公式。

正文首先作为草稿保存，然后在编译准备阶段解析 AST，按节点白名单验证并生成受控 TeX。遇到不支持的 Markdown 节点、过深列表或不安全链接时，显示位置和修改建议，拒绝本次编译，不能悄悄删除内容；草稿和最后成功 PDF 不受影响。

不提供原始 LaTeX 入口。`\input{...}` 等命令样字符串只能作为普通文字整体转义，不可直接拼入 TeX 源码；转义须逐字符覆盖 `& % $ # _ { } ~ ^ \`，避免替换顺序重复转义。原始 HTML 节点不得进入渲染树。AST 节点校验、转义正确性和 PDF 语义保留在 M1/M3 验证；M0 的结构检查不声称能安全渲染 Markdown。

## 4. 保存、编译与版本

SQLite 是事实来源。客户端提交内容与 `expected_revision`；服务端在事务中比较当前修订，不相符返回冲突，不使用最后写入覆盖。多标签页发生冲突时保留本地输入，提供重新载入或另存新简历，不自动合并。

只有持久化提交成功才能返回新 `revision` 和显示“已保存”。串行发送当前简历的保存请求；若请求途中又有输入，响应只确认已发送快照，后续修改仍为未保存。网络/事务失败不得递增确认修订或触发新版编译。

编译任务读取不可变的已保存快照，键至少包含简历 ID、revision、模板版本、引擎版本、字体集合指纹。任务状态为 `queued/running/succeeded/failed/cancelled/timed_out`；对旧任务的完成通知，只有其键仍等于当前目标键才可更新当前预览。只比较任务结束先后不够；引擎/字体变化但 revision 不变也要重新编译。

预览引用成功产物及其键，导出读取同一文件，不单独重新生成。存在未保存修改、预览键落后或仍在编译时，默认不允许直接导出“最新版”；明确选择“导出上次成功版本”后才可下载，并在确认框及文件名中标注修订。没有成功产物时无任何可导出 PDF。

## 5. 附件和备份

仅允许一张头像：PNG/JPEG，原文件不大于 5 MiB，解码后单边不超过 4096 px。附件字段为 `id`、`media_type`、`byte_size`、`sha256`、`width_px`、`height_px`。存储路径由程序生成，不接收用户路径。必须通过实际解码确认类型、尺寸并移除元数据；哈希对应最终存储字节，不能只相信扩展名和客户端声明。

备份是一份简历的 ZIP，建议扩展名 `.resume.zip`。备份格式版本 `backup_version=1`，对应 `schemas/backup-manifest.schema.json`。

```text
manifest.json
resume.json
assets/<attachment-id>.png  # JPEG 使用 .jpg；没有头像时无 assets 条目
```

manifest 包含 `backup_version`、`resume_schema_version`、`resume_id`、`revision`、`created_at`、`files`。每个文件记录精确 `path`、字节长度和 SHA-256，附件另有 `attachment_id`；manifest 自身不列入哈希清单，PDF 缓存、SQLite 文件、运行时、日志不进入备份。

创建备份必须先完成当前保存，并从同一不可变快照收集附件；即使 PDF 编译失败也能备份。导入顺序：限流和大小预检、严格解析清单、验证全部文件、验证 schema/引用/哈希、暂存附件、事务落库、原子发布。任何失败不产生半份简历；原有简历不受影响。

安全限制：压缩包最多 25 MiB、解压总量最多 50 MiB、条目最多 3 个（manifest、resume、可选头像），manifest 最多 64 KiB。不允许目录条目、符号/硬链接、设备文件、加密文件、重复 ZIP 成员、未列出的文件、绝对路径、反斜杠、`..`、嵌套压缩包。按实际解压字节限流，不能只相信 ZIP 头。文件名必须精确匹配契约，不进行“清洗后继续解压”。这些归档安全操作在 M2/M4 实现并验证。

首版导入始终创建副本，即使没有 ID 冲突也不覆盖现有记录；对简历及所有内部 ID 重新映射，revision 重置为 1，创建/更新时间设为导入时间，标题加“（导入）”并截断到长度上限。内容、顺序、显隐、设置和附件字节保持一致。备份往返比较语义，不比较新 ID 和系统时间。删除原始简历需另行确认。

未知新版本明确拒绝并提示需要升级；尚不存在已发布的 v0 迁移规则，`schema_version=0` 测试当前只证明拒绝，不伪造旧版本兼容性。

## 6. 多份简历与复制

管理页支持新建空白、从示例新建、创建副本、重命名、删除与切换。管理名称不显示在 PDF 正文中，允许重名，身份始终由稳定 ID 决定；自动建议的副本名应避开现有名称，并保持 80 字符上限。

创建副本默认读取源简历的已保存快照。若存在未保存草稿，界面必须明确区分“已保存版本”与“包含未保存修改的当前草稿”，不得无提示混用。复制不保存、不修改源简历；副本从 revision=1 开始，拥有新简历 ID、创建/更新时间，且不继承源 PDF 的成功状态。

生产复制必须重新生成模块、条目、链接和附件 ID 并改写内部引用。内容、顺序、显隐、模板、样式和附件字节保持语义一致；采用独立附件文件，或经过验证的不可变内容寻址及引用计数，不能让删除原简历顺带删除副本仍使用的头像。事务失败不得产生不完整副本或改变源记录。M0 演示对象尚非正式 JSON Schema，当前模型仅证明独立快照与任务归属，不声称完成附件复制和事务实现。

重命名只作用于目标简历，更新修订和更新时间，旧预览按过期处理。删除必须显示目标名称并二次确认；若有未保存草稿，明确说明草稿也会删除；取消和 Esc 不产生删除。删除原简历与删除副本都不影响其他简历。删除/重命名/复制在目标保存或编译进行中暂时禁用，其他简历可继续编辑。

每份简历分别维护未保存草稿、确认修订、保存状态、编译任务和最后成功 PDF；任务完成时按简历 ID 与任务 ID 回写，不按当前打开的页面回写。切换简历不自动丢弃草稿，返回后必须恢复对应内容；正式持久化故障仍不得显示虚假“已保存”。M0 的页面内切换保留仅是内存行为，刷新、关页、跨浏览器标签并不持久化或共享。
