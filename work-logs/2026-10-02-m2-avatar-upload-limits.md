# M2 头像上传要求统一

## 目标与实现

- 用户可见要求为 JPG/JPEG、PNG，上传文件不超过 1 MB。使用十进制 1 MB = 1,000,000 字节，等于上限允许，大于上限拒绝。
- 前端选择文件时先检查扩展名（忽略大小写）与文件大小，再发送请求；允许浏览器未提供 MIME，由后端检测真实图像内容。后端按实际请求流累计字节，不能只靠前端绕过。
- 删除原上传“单边不超过 4096 像素”规则，不要求固定长宽或比例。合法图片按 EXIF 校正方向，等比例缩小至适合头像的最长边 1024 像素，透明区域合成白底并清理元数据；小图片不放大。
- 后台保留有效图像解码及 16,777,216 总像素的资源保护，避免小压缩文件触发巨额内存分配。这不是要求用户上传固定分辨率。
- 1 MB 针对新上传原文件；历史已存头像及工程备份继续沿用原 5 MiB/4096 存储契约，不破坏旧数据。

## 验证进度

- 125 项 Python / 46 项 Node 测试通过，覆盖格式、1 MB 精确边界、伪装/损坏图片、超大解码、长边超 4096 的宽/竖图、方向与透明处理，以及超过新上传上限的旧备份仍可导入/渲染。
- 真实 HTTP 自检通过：超限请求返回 413 且原记录不变；5000×1000 的合法 PNG 自动生成 1024×205 的头像并真实编译为一页；原一页/两页基准和头像备份往返通过。证据为 `docs/m2/results.json` 的 `avatar_one_mb_limit_and_wide_photo_normalization`。
- 实际用户头像不替换，测试只使用生成的纯色图片。
- 8770 服务已更新，页面确认上传提示为 JPG/JPEG/PNG、1 MB，文件选择器接受三种后缀；无控制台错误或警告。用户最新 r39 的内容和已有头像保持，截图仅放在忽略的私有目录。

## 边界

不声称接受任意恶意或超大解码图片。仍是本机开发服务，不恢复已跳过的干净 Mac 验收。
